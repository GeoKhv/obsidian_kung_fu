# Как устроены задачи в моём Obsidian

## Установка

1. Включить встроенный Daily Notes. Формат имени: `YYYY-MM-DD`.
2. Установить [Tasks](https://github.com/obsidian-tasks-group/obsidian-tasks).
3. Установить [Daily Checkbox Focus](https://github.com/GeoKhv/obsidian-daily-checkbox-focus) и [Tasks Inline Edit](https://github.com/GeoKhv/obsidian-tasks-inline-edit) по инструкциям в их репозиториях. У каждого есть готовые файлы в GitHub Releases.
4. Скопировать [daily v2.md](../templates/daily%20v2.md) в папку шаблонов и выбрать его в Daily Notes. У меня ежедневники лежат в `Alfa/WRK`.
5. Скопировать [Daily Task Blocks.css](../snippets/Daily%20Task%20Blocks.css) в `.obsidian/snippets/` и включить его в настройках оформления.
6. Настроить статусы Tasks и определение плановой даты по имени файла, как описано ниже.

Шаблон содержит мой путь `alfa/wrk` в фильтрах. Для другой папки его нужно заменить. Для фильтров личных задач используются `#personal` и заголовки `personal`, `todo.family`, `life`, `hobbies`.

## Статусы Tasks

Важно настроить тип статуса, а не только символ: запросы разделяют задачи по `status.type`.

| Символ в Markdown | Название | Тип Tasks | Куда попадает |
| --- | --- | --- | --- |
| `[ ]` | Todo | TODO | Мои действия |
| `[/]` | In Progress | IN_PROGRESS | WORK — В работе; для PERSONAL — общий список действий |
| `[w]` | Waiting | ON_HOLD | Ожидаю ответа / результата |
| `[x]` | Done | DONE | Finished в дату завершения |
| `[-]` | Cancelled | CANCELLED | Finished в дату отмены |

У меня также настроены `I` → Information, `i` → Idea, `?` → Question и `!` → Important. IDEA выбирает их по имени статуса. Important в текущем шаблоне может присутствовать и в обычном списке действий: IDEA — дополнительное представление, а не взаимоисключающая категория.

В Tasks включены автоматические даты создания, завершения и отмены, а также **Use filename as Scheduled date**. Поэтому задача из ежедневника без явно заданной плановой даты получает её из имени файла. Настройка даты сама по себе не переносит текст задачи между заметками.

## Ввод и распределение

Сверху ежедневника, до первого заголовка, остаётся обычная строка `- [ ] `. Daily Checkbox Focus при открытии заметки ставит туда курсор. По умолчанию поиск ограничен областью до первого заголовка; если пустой строки нет, плагин может создать её. Область поиска и автоматическое создание настраиваются отдельно.

Дальше идут результаты запросов Tasks:

- WORK разделён на TODO, IN_PROGRESS и ON_HOLD.
- PERSONAL объединяет TODO и IN_PROGRESS в «Мои действия», а ON_HOLD показывает отдельно.
- WORK исключает личные теги и личные разделы. Совпадение `#personal` точное или с вложенным тегом: `#personal/home` подходит, `#personality` — нет.
- Рабочие и личные списки исключают папки `archive` и `templates`.
- Рабочие действия и работа учитывают дату начала; ожидание не ограничено этой датой. Личные действия показывают задачи без дат либо с датой события не позже даты ежедневника.
- В рабочих списках действий и работы сначала идут важные задачи со сроком до следующего дня включительно, затем важные, затем срочные, затем остальные. Дальше учитываются приоритет, дедлайн и текст.
- Finished выбирает DONE и CANCELLED по дате текущего ежедневника. IDEA и Finished в текущем шаблоне являются общими для хранилища: у них нет фильтра WORK/PERSONAL и исключения архивов.

Это представления существующих задач. Если задача написана в другой заметке и подходит под фильтр, она появляется в списке без копирования исходной строки.

## Редактирование прямо в списке

Tasks Inline Edit работает с результатами запросов Tasks в Live Preview и режиме чтения:

- клик по обычному тексту задачи включает редактирование;
- `Enter` сохраняет, `Escape` отменяет;
- уход из поля сохраняет изменённый текст;
- чекбокс, меню статуса, кнопка редактирования Tasks, даты и ссылки сохраняют свои действия;
- пустое место списка не раскрывает исходный код запроса в Live Preview.

Плагин сверяет исходную строку и изменяет только описание. Даты, статус, отступы, идентификаторы и другие распознанные метаданные сохраняются. При неоднозначном совпадении или конфликте он отказывается от записи. В таком случае остаётся штатная кнопка редактирования Tasks.

## Контекст подзадач

Вложенность задаётся обычными отступами в исходной заметке. В списке под подзадачей появляется строка `↳ Родитель`, а для нескольких уровней — цепочка. Контекст может включать и обычные пункты списка между задачами.

Каждая подзадача фильтруется по своему статусу. Завершение одной подзадачи не завершает родителя и соседние задачи. Клик по предку открывает его точную строку в редакторе, чтобы можно было прочитать постановку целиком.

Контекст можно выключить: **Настройки → Tasks Inline Edit → Показывать контекст родительских задач**. Перезапуск не нужен; настройка сохраняется.

В запросах используется `hide tree`. Режим `show tree` в Tasks выводит также дочерние элементы, которые не прошли фильтр запроса, поэтому для независимых списков статусов здесь используется плоская выдача с подписями. В уже отображённом дереве вложенные строки дополнительных подписей не получают.

Ограничения:

- Если текст, статус и ссылка на источник не позволяют отличить две задачи, подпись не показывается. Плагин не угадывает родителя.
- После изменения исходной строки переход может быть временно отклонён до обновления кэша Tasks.
- Проверены Tasks 8.4.0/8.5.0 на уровне адаптера; живая приёмка текущей версии выполнена с Tasks 8.5.0. Неизвестные версии не получают небезопасное редактирование или угаданный контекст.
- Контекст рассчитан на основное окно desktop Obsidian. Дополнительные окна и мобильный сценарий не проверены.

## Оформление

Цвета блоков и иконки статусов задаёт отдельный CSS, а не Tasks Inline Edit. CSS привязан к метаданным callout: `task-progress`, `task-waiting`, `task-todo`, поэтому сам по себе не меняет остальные блоки заметок.

В моей установке используется Obsidian Nord, Style Settings и дополнительный сниппет S - Checkboxes. Они отвечают за вид интерфейса. Логика статусов, запросов и контекста работает отдельно от темы.

## Проверка после настройки

Создать отдельную тестовую заметку с родителем и двумя подзадачами. У родителя выбрать IN_PROGRESS, у одной подзадачи TODO, у другой DONE. Проверить, что задачи видны в соответствующих списках, у подзадач есть контекст, ссылка открывает родителя, а редактирование в выдаче меняет правильную исходную строку. Дату завершения нужно выбрать равной дате открытого ежедневника, чтобы задача попала в Finished.
